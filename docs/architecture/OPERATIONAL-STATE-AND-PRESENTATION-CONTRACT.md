# Оперативное состояние, события и динамическая мнемосхема — целевой контракт

**Status:** target design, not implemented. **Work item:** PRODUCT-SCOPE-AND-OPERATIONAL-UX-ARCHITECTURE-001 (#41). **Related:** WS-6 accepted foundation; Issue #39 — UX/event replay; Issue #40 — АПВ. Это design contract, **не новый принятый runtime API или schema**.

[Граница продукта](PRODUCT-BOUNDARY-AND-WORKSPACE-MODES.md) · [roadmap](../roadmap.md) · [фактический статус](../PROJECT-STATUS.md).

## 1. Неизменяемый источник истины

`CanonicalModel` содержит инженерные элементы/терминалы/соединения/параметры и их canonical IDs. Конкретное наблюдаемое состояние является **снимком**, который ссылается на модель и её fingerprint.

```text
  Canonical electrical model (model_id + revision/fingerprint)
                         |
             Scenario / Snapshot context
              /          |            \
    Source boundaries  SolverResults  Observations (optional import)
              \          |            /
             Qualified state / measured-value attribution
                         |
          Switch operation + protection event timeline
                         |
              Presentation snapshot (read-only)
               /            |              \
          Visio overlay   Device card    Event/replay panel
```

**Важные разграничения:**

- `topologically_energized` (WS-6): терминал достижим от одного или нескольких **явных** активных источников через допустимые проводящие связи; это **не** измеренное напряжение и не доказательство отсутствия/наличия потенциала.
- `voltage_class` / `nominal_voltage_v`: инженерный класс/номинал. Значение **не** является показанием в момент времени.
- `VoltageMeasurement` и `CurrentMeasurement`: квалифицированные величины с единицами, компонентой/фазой, местом измерения, временем, происхождением, качеством.
- `SwitchPosition`: положение контактов/тележки; отдельно команда/квитирование/подтверждённое положение. Для открытого выключателя напряжение на сторонах A и B может сохраняться независимо.
- `earthing_state`: отдельная проверенная семантика заземлителя/земли, **не** выводится из белой окраски или отсутствия источника.
- `fault_location` и `alarm`: самостоятельные события, не смешивать с окраской уровня напряжения.

## 2. Проектируемые DTO (не утверждённые имена schema)

Предлагается согласовать такие **версируемые границы**, не заменяя существующие контракты без отдельной миграции:

| DTO / entity | Минимальные поля / смысл |
|---|---|
| `PresentationContext` | `model_fingerprint`, `scenario_id`, `snapshot_id`, `time_s`, `workspace_mode`, `data_source_kind`, `source_reference` |
| `TerminalStateSample` | `element_id`, `terminal_id`, `reachable_sources[]`, `topologically_energized: true/false/unknown`, `provenance` |
| `ElectricalQuantitySample` | `element_id/terminal_id` или `branch_id+side`, `quantity_kind`, `phase/sequence`, `value`, `unit`, `time`, `value_origin`, `quality`, `study_id` |
| `ApparatusStateSample` | `element_id`, `contact_position`, `withdrawable_position`, `feedback_quality`, `command_id`, `last_confirmed_change` |
| `DomainEvent` | `event_id`, `scenario_id`, `sequence`, `logical_time_s`, `element_id`, `event_type`, `causation_id`, `origin`, `payload`, `quality` |
| `PresentationSnapshot` | `context`, immutable terminal/equipment/quantity views, timeline cursor, legend/palette ID, warnings; **без Visio COM объектов** |
| `PresentationDelta` | `from_snapshot`, `to_snapshot`, canonical IDs изменившихся объектов и рассчитанные представления; допустим только если ревизии/версии совместимы |
| `VisioProjectionBinding` | уникальные `document_identity`, `page_id`, `shape_id`, `canonical_element_id`, `shape_family`, `binding_source`, `verified_model_fingerprint` |

`value_origin` должен сохранять отличие `measured/imported`, `calculated`, `simulated`, `entered`; `quality` отдельно описывает `valid`, `stale`, `unknown`, `invalid`, `conflicting`, `not_supported`. Нельзя подменять отсутствие значения нулём. Время расчёта — логическое; timestamp внешнего сигнала — от источника, хранится отдельно, а порядок для одинаковых времён задаётся `sequence`.

Не обещать реальный timestamp мс, если данные/solver предоставляют только срезы в заданные моменты. Для solver results обязательны метод, версии, исходные условия, граница применимости, статус и ссылка на конкретный запуск.

## 3. Электрическая топологическая раскраска — не декоративный слой

### Режимы палитры (выбираемые)

1. **Наличие питания + класс напряжения** (default): если `topologically_energized=true` и `voltage_class` достоверно известен — цвет класса; если однозначно нет доступного источника в полностью квалифицированной топологии — белый/нейтральный; при unknown — особый штрих/маркер, **не белый**.
2. **Только классы напряжения** (без топологии): всегда инженерный класс, независимо от состояния; явно маркируется как конструктивная окраска.
3. **По питающим источникам / трассировка**: выделение reachable source(s); для двух источников не угадывать «главный» — двойной/штриховой маркер и подробная карточка.
4. **Режим переключений/поиска путей**: просветить выбранные терминальные пути, состояние каждого аппарата и потенциальные изменения; независимая подложка топологической окраски.

Палитра задаётся versioned локальным profile. Российские референсы помогают выбрать **начальные настройки**; цвета NPT/СК-11 и ГОСТ не объявляются универсально обязательными без проверки применимости. Доступна пользовательская перенастройка цветов/темы и легенда по реальным значениям классов. Контраст, чёткие границы, читаемость на печати и без цветового зрения обязательны.

### Приоритет индикаций / fail-closed

**Не делать один цвет кодом нескольких независимых состояний.**

- **Основной электрический цвет** = класс/режим раскраски при квалифицированной топологии.
- **Качество/неизвестность** = независимый штрих, знак `?`, текст/подсказка и явный badge (в том числе недоступный/stale solver или сигнал).
- **Аварии/РЗА/ограничения** = отдельная рамка/иконка/мигание только при пользовательской настройке, журнал события и явный текст причины.
- **Заземление/ремонт/плакаты** = отдельные проверенные символы/пометки с приоритетом safety-информации; не перекрашивать в «обесточено» и не скрывать статус неизвестного питания.
- **Коммутационные аппараты** = контактная позиция, доступность управления, разрешение, неподтверждённая команда независимо от состояния присоединения.

Белая линия **не подтверждает электробезопасность**: топологически «обесточено» ≠ проверенное отсутствие напряжения ≠ заземлено. При неизвестной/неполной топологии и непроверенных источниках запрещено отображать белое как доказанно обесточенное. Если измеренное U не согласуется с вычисленной топологией — предупреждение о противоречии и оба значения с происхождением, **не автоматическое усреднение**.

### Как красить физическую схему

Раскрашивать геометрически связанные объекты по **canonical terminal/connection segments**, а не целиком аппарат/ячейку из одного общего boolean: разомкнутый выключатель может иметь одну или обе стороны под напряжением. Примитивы `line/bus/connection` и терминалы должны иметь явную визуальную привязку; если legacy-геометрия/Glue неоднозначна — вывести `unknown` и потребовать разбор связи.

## 4. Контракт поведения UI, а не копия SCADA

**Одна редактируемая исходная схема Visio; отдельное непостоянное runtime-представление.** Предпочтительный UX — Visio с Ribbon/контекстной карточкой и модельной боковой панелью: схема занимает основную область, информация открывается по запросу. На схеме только необходимые U/I/статус, а не непрерывные числа на каждом объекте.

- **Контекстная карточка:** имя/тип, canonical ID, напряжение/номинал, топологические источники, обе стороны аппарата, текущее моделируемое/архивное состояние, качество, уставки/пуск/срабатывание, предупреждения, доступные **локальные модельные** действия.
- **Расчётные значения:** возле оборудования выборочные `U/I/P/Q` в единицах, отдельная карточка для подробностей, «Нет данных» если не рассчитано; при неуспешном study не показывать прежние величины без метки stale и связи со старым snapshot.
- **Журнал событий:** сортировка `logical_time_s + sequence`; отдельные пуск/выдержка/срабатывание РЗА, команда, подтверждение фактического модельного положения, изменение source attribution, блокировки, возможный АПВ; быстрый переход к аппарату/моменту.
- **Шкала:** пауза, шаг назад/вперёд, позиция времени, скорость демонстрационного воспроизведения и Reset; возврат к любому моменту **не переисполняет реальные команды или Visio `Row_1` toggles**.
- **Тренды/осциллограммы:** различать набор рассчитанных точек, дискретную временную модель, настоящий измерительный архив и импорт COMTRADE; не интерполировать как «физический переходный процесс» без соответствующего решателя.
- **Alerts:** в локальном помощнике существуют `scenario_event` и `warning`; `acknowledge` локального просмотра/тренировки **не заменяет** квитирование промышленной SCADA.

### Внешний вид/присутствие

Не создавать автоматически страницы `UI-*`, `QoL-*`, тестовые ячейки и постоянные дополнительные символы. В runtime пользовательские обозначения/позиции печатной схемы сохраняются. Динамический слой может быть отдельным некоммитящим desktop overlay или временной проекцией **только после проверенного экспериментом** восстановления оригинальных ShapeSheet-данных и native Undo. Нельзя заранее утверждать, что любой Visio 2010 поддерживает новый неразрушающий overlay способ; выбирать по capability matrix/spike.

## 5. Временная/событийная модель

В основе сценария — immutable initial model fingerprint + explicit source refs + список детерминированных событий и дискретных снимков. Любой переход воспроизводим из начальных данных и версии алгоритма. Событие содержит `causation_id`, чтобы связать:

```text
fault_initiated
  -> protection_pickup -> protection_operated
  -> breaker_trip_requested
  -> breaker_open_command_issued (simulation)
  -> breaker_open_confirmed (simulation)
  -> topology_recalculated -> solver_study_completed/unsupported
  -> presentation_updated
```

Запрос на переключение **не равен** подтверждённому положению. При `block/invalid/unknown` никакая недоказанная коммутация не отображается как выполненная. `replay` вычисляет последовательность presentation snapshots из сохранённых event/state records, **без повторного переключения Visio ShapeSheet или оборудования**. Временная шкала должна сохранять sequence для равных моментов.

### Будущее АПВ: отдельная автоматика, а не таймер UI

`APV-enabled` не определяется просто меткой на символе; требуются явно квалифицированные настройки, допустимость по причине отключения, условия разрешения, блокировки, число попыток, выдержки, подтверждения положений, реакция на устойчивое/неустойчивое повреждение. Сценарии:
- `trip -> open confirmed -> APV armed -> dead time -> close requested -> close confirmed -> fault absent -> success`;
- `... -> close confirmed -> persistent fault -> trip -> lockout/unsuccessful`;
- `... -> blocked/not armed` с указанием условия.
Аттестовать «Успешное АПВ» допустимо только после подтверждения моделируемого **включения и дальнейшего состояния сети**, а не отправки команды. `AUTO-RECLOSING-APV-001` — Issue #40; до него интерфейс честно отключает управление/индикацию АПВ.

## 6. Контроль переключений и бланков

Модельная операция: `proposed -> validated/blocked -> request -> modeled position confirmed/failed/unknown -> topology delta -> documented outcome`. Нормативные правила, заземления и interlocks требуют отдельного permission contract; существующий необязательный validator не следует представлять как сертифицированный safety-gate.

Бланк — локальный **проект/симуляция документа**, а не выполнение распоряжения на объекте. Требуются идентификаторы версии исходной/конечной схемы, атрибуты разрешений, шаги, пред-/постусловия, ручное подтверждение и отчёт. Генерировать «допущено» только по полному перечню квалифицированных проверок; неполнота = блок или явное ограничение, не зелёная галочка.

## 7. Архитектурные интерфейсы и ответственность

| Слой | Что делает | Что запрещено |
|---|---|---|
| `core/domain` | инженерная модель, топология, идентификаторы | знать Visio/colour/решатель |
| `operational` | терминальная достижимость, переключения, attribution и события | выводить фазное U/I из геометрии |
| `solvers` | электроизмеримые расчётные результаты, статус/версия | менять switch state или ShapeSheet |
| `protection` | уставки/логика/события/request | само исполнять команды в Visio |
| `scenario/time` (план) | локальный immutable сценарий, журнал, снимки, replay | постоянный сервер SCADA |
| `presentation` (план) | data quality + топология → чистые DTO/палитры/legend | генерировать значения измерений |
| `frontends/visio` | привязка canonical IDs, локальные панели, команды редактирования и renderer | быть источником электрической истины |
| `documents` (план) | печать/экспорт бланков и отчётов | брать неподтверждённые данные без provenance |

**Зависимости:** `core/domain -> operational/solvers/protection -> scenario -> presentation -> Visio`. Imports «вверх» недопустимы. Runtime Visio COM и standalone packaging — изолированная host/transport boundary; Master MCP только для разработки/приёмки.

## 8. Набор проверок, чтобы этот документ стал runtime-контрактом

1. По одной canonical схеме с 2 источниками проверить обе стороны разомкнутого выключателя, разные классы напряжения, трансформатор и альтернативное питание.
2. Неквалифицированная/отсутствующая связь и недостоверный сигнал должны давать `unknown` с отдельной индикацией, **не белый**.
3. Рассчитанное U и топологический статус противоречат друг другу → warning со ссылкой на обе записи, без переписывания модели.
4. Действие выключателя изменяет `terminal_delta` и presentation snapshot, а не ShapeSheet-engineering payload. Preview/Replay не меняет рабочий `.vsdm`.
5. Три ветки АПВ (успешное, неуспешное, блокированное) можно воспроизвести с timestamps после реализации Issue #40; до этого APV controls disabled.
6. Неверный solver/protection/profile/vintage fingerprint исключает применение устаревшего runtime snapshot.
7. Visio v2010+ capability matrix, Win10/11, x86/x64; DPI/печать/Undo/сложные legacy master shapes тестируются отдельно.
8. Тестовая схема находится в отдельном disposable документе, а cleanup проверяет отсутствие созданных страниц/элементов, сохранность хеша оригинального документа и исходных состояний.
