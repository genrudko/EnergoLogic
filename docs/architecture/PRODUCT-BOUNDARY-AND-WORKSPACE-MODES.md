# EnergoLogic — назначение продукта и режимы работы

**Решение владельца:** 2026-10-08. **Статус:** целевой канонический контракт, утверждается отдельно от реализации. **Work item:** PRODUCT-SCOPE-AND-OPERATIONAL-UX-ARCHITECTURE-001 / Issue #41.

## 1. Что такое EnergoLogic

**EnergoLogic — автономный инженерно-оперативный помощник** для начальника смены, диспетчера, инженера по оперативной работе, ДЭМа и другого электротехнического персонала. Цель — быстро рисовать и проверять схемы, выполнять режимные расчёты, моделировать коммутации и РЗА, готовить и проверять бланки переключений, разбирать аварийные ситуации.

Продукт локальный, рассчитан на одного пользователя или небольшую группу специалистов, умеющих обмениваться проектами и документами без обязательного сервера. Его достоинство — инженерная полнота и удобство, **не** повторение масштаба промышленной SCADA.

### Обязательные продуктообразующие задачи

1. **Электрические схемы в Microsoft Visio:** импорт и редактирование legacy схем, каноническая привязка оборудования, генерация, ГОСТ/отраслевая семантика и печать.
2. **Расчёты:** установившийся режим, потокораспределение, токи КЗ и квалифицированные производные проверки с явными исходными данными, настройками и ограничениями решателя.
3. **Оперативный анализ:** запитанность участков, трассировка источников, переключения, оценка последствий, явная недостоверность/неполнота данных.
4. **РЗА и автоматика:** проверка уставок и селективности, события пуска/срабатывания, явные запросы/факты коммутации, позже АПВ и другие функции по отдельным контрактам.
5. **Бланки переключений:** проект, этапы и подтверждения, условия, блокировки с объяснениями, предварительная проверка, печатный документ и локальная история.
6. **Разбор аварий и обучение:** воспроизводимые сценарии, сравнение вариантов, шкала времени, пояснение последствий, экспорт отчёта.

### Не входит в основной продукт

- Прямая выдача команд реальным выключателям, удалённое телеуправление, ответственность системы промышленной автоматики за безопасность.
- Обязательные постоянные подключения к IEC 60870-5-104, IEC 61850, OPC UA, серверы телемеханики, регистраторы на объекте; возможные импортеры/адаптеры — только отдельный будущий opt-in.
- Круглосуточный отказоустойчивый SCADA-сервер, кластер, единый диспетчерский центр, распределённый realtime historian, видеостена, корпоративная AAA-инфраструктура.
- Динамическая имитация электромеханических переходных процессов без отдельного квалифицированного решателя; серия расчётных снимков не должна называться непрерывным физическим переходным процессом.
- Автоматическое подтверждение соответствия нормативам без версионированной применимости правил и источников.

**Граница:** SCADA и российские диспетчерские комплексы — функциональные референсы, но не технологическая база, не шаблон масштабирования и не источник нормативного права.

## 2. Платформа и ограничения

- Windows 10/11 + установленный Visio **2010 — последняя поддерживаемая desktop-версия**; проверять фактические версии и x86/x64. Факт совместимости только по матрице испытаний, не по одному установленному Visio 16.x.
- Полностью автономный комплект зависимостей: встроенные runtime/библиотеки/решатели/ГОСТ-элементы; без необходимости отдельно устанавливать Python, .NET-компоненты, pip, Git, Node или обращаться в интернет; упаковка может состоять из нескольких процессов и обычного установщика.
- Русский интерфейс и профессиональная русская терминология; идентификаторы Python/API/schema на английском, связанные с контролируемым RU↔EN Registry.
- **Canonical model = source of truth**. Visio — внешний вид, ввод и проекция. Расчётный движок, журнал, РЗА и документы используют одни и те же canonical IDs, не угадывают связи по координатам.
- Local-first: проект переносим между ПК; резервное копирование, самодостаточность, открытие без VPS/MCP/сети. Текущий Master MCP — **инструмент разработки и приёмки**, а не production dependency продукта.
- Критические вычисления детерминированы, headless-testable, fail-closed. Обновление UI не выдаёт разрешение на реальные переключения.

## 3. Две независимые оси UX

Режим рабочего места и **источник состояния** различны. Нельзя заводить четыре независимых редактора/мнемосхемы.

| Режим | Главная задача | Может менять canonical модель? | Может менять состояние сценария? |
|---|---|---|---|
| **Редактирование** / `edit` | Visio-геометрия, связи, оборудование, параметры | Да, явно, через проверки/Undo | Нет, только инициировать отдельный сценарий |
| **Оперативный просмотр** / `operational_view` | Чтение схемы, источники, состояния, измерения, диагностика | Нет | Нет |
| **Моделирование / тренажёр** / `simulation` | Что-если, переключения, режим, РЗА, АПВ, бланки | **Нет**, изменяется только изолированная модель сценария | Да, с журналом |
| **Ретроспектива** / `replay` | Разбор сохранённого сценария/архива на момент времени | Нет | Нет; seek/playback воспроизводит готовые снимки |

Источник состояния — отдельное измерение:

| Тип источника | Семантика |
|---|---|
| `model_snapshot` | Явно заданное состояние проекта/схемы |
| `calculated` | Результат конкретного решателя и набора входных параметров |
| `simulation` | Вычисленное состояние изолированного сценария |
| `imported_observation` | Загруженная запись внешней системы с временем и качеством |
| `archive` | Сохранённые immutable состояния и события; исходное происхождение **сохраняется** |

Пример: в оперативном просмотре пользователь может выбрать `calculated`, а в ретроспективе — ранее сохранённые `simulation` либо `imported_observation`. «Оперативный просмотр» **не означает** работающую промышленную телеметрию. Слово **Live** допустимо только как явно маркированное представление текущего *выбранного источника* (например «Моделирование — сейчас»), не как обещание связи с объектом.

### Переключение режимов

- Перед выходом из `edit` сохранить или отменить изменения через обычный UX, не тайную мутацию.
- В режимах чтения/моделирования запрещены случайные правки геометрии и инженерной модели. Сценарий создаёт копию начального состояния с идентификатором/фингерпринтом; Reset возвращает копию к исходному снимку.
- Переключение `simulation` → `edit` не оставляет окраску, события, телеметрию, позиции символов или дополнительные страницы Visio в сохранённой схеме.
- Одно окно может содержать рабочую схему, контекстную карточку аппарата, результаты расчётов, события и контролы времени; без дублирования той же модели в разных модулях.

## 4. Рабочие сценарии как продуктовый критерий

- **Нарисовать/импортировать КРУ-35 кВ:** инженер привязывает топологию, исправляет неоднозначности, подтверждает атрибуты оборудования; импорт не присваивает «доверенное» состояние только из визуального сходства.
- **Рассчитать режим:** выбрать явные исходные данные, получить таблицу/схему (U, I, P, Q), ограничения и отчёт; если величина не вычислена — «Нет данных».
- **Что произойдёт при отключении:** открыть сценарий без изменений документа, выполнить коммутацию, увидеть обесточенные секции, альтернативные источники, предупреждения и новый расчёт при его наличии.
- **Проверить МТЗ/АПВ:** время пуска, выдержку, запрос на отключение, **фактическое моделируемое** положение выключателя, условия повторного включения, успешное/неуспешное/блокированное АПВ, timestamp и причины; пока АПВ не реализовано, UI честно показывает «Функция недоступна».
- **Подготовить бланк:** исходная/целевая схема, генерация проекта шагов, проверки, ручные подписи/подтверждения, просмотр последствий, экспорт/печать. Моделирование не является командой реальному оборудованию.
- **Разобрать аварию:** локальный файл со снимками/событиями, шкала времени, выбор аппарата, provenance измерений, просмотр логики РЗА и отчёт.

## 5. Критерий готовности функции

Нельзя считать функцию готовой лишь потому, что headless тесты прошли или одна фигура Visio переключилась. Требуется: инженерный контракт → синтетические/golden тесты → реальный доступный Visio fixture/офлайн пакет (по применимости) → пользовательский сценарий → проверка возврата/Undo и чистоты документа → доказательства. Документы на практике не должны обрастать страницами `UI-*`/`QoL-*`: тестовый документ/проект изолирован, cleanup обязателен и верифицируется.
